# AIDE 연구 과정

**이 전체 과정 — 연구부터 토론, 최종 작성까지 — 은 AI 에이전트가 수행했습니다.** 인간은 방향 설정과 리뷰를 제공했고, 에이전트가 모든 연구, 분석, 토론, 집필을 수행했습니다.

## 개요

AIDE 방법론은 여러 AI 모델의 강점과 대립적 토론을 활용하기 위해 설계된 엄격한 3단계 연구 과정을 통해 개발되었습니다.

### 1단계: 독립적 딥리서치

3개 주요 AI 모델이 동일한 핵심 질문에 대해 독립적으로 딥리서치를 수행했습니다: *에이전트 시대에 소프트웨어 아키텍처는 어떻게 진화해야 하는가?*

각 모델은 고유한 관점, 학습 데이터, 분석 방식을 제공하여 다양한 시각을 확보했습니다.

### 2단계: 대립적 팀 토론

상반된 철학적 입장을 가진 두 에이전트 팀이 구성되었습니다:

- **Team Alpha (통합파)** — 기존 방법론의 진화적 적응을 주장. 현재의 모범 사례를 에이전트에 맞게 확장할 수 있다고 봄.
- **Team Beta (급진파)** — 소프트웨어 아키텍처의 근본적 재구축을 주장. 에이전트 시대에는 완전히 새로운 원칙이 필요하다고 봄.

각 팀에는 연구원과 시니어 개발자가 포함되어 실용적 vs 이론적 관점을 토론했습니다.

### 3단계: CTO 에이전트 최종 판단

CTO 페르소나 에이전트가 모든 연구 보고서와 토론 기록을 검토한 뒤, 양측의 가장 강력한 논거를 종합하여 통합된 AIDE 방법론으로 최종 판단을 내렸습니다.

## 읽는 순서

1. **3개 딥리서치 보고서**부터 읽어 기초 분석을 이해합니다.
2. **팀 토론 보고서**를 읽어 경쟁하는 철학이 어떻게 검증되었는지 봅니다.
3. **AIDE 방법론 본문**을 읽어 최종 종합 결과를 확인합니다.

연구 보고서들은 역사적 기록으로 보존됩니다. 최종 방법론으로 정제되기 전의 원시적 사고를 담고 있습니다. 보고서와 최종 방법론 사이의 차이는 예상되는 것입니다 — 그것이 종합의 본질입니다.

## 연구 방법

- 각 AI 모델은 동일한 상위 수준 프롬프트를 받았지만 자유롭게 연구하도록 허용되었습니다.
- 연구 단계에서 모델들은 서로의 결과물을 볼 수 없었습니다.
- 토론 팀에게는 모든 연구 보고서에 대한 접근 권한이 주어졌습니다.
- CTO 에이전트는 모든 것에 접근할 수 있었습니다: 연구, 토론 기록, 이전 초안.
- 인간의 참여는 다음으로 제한되었습니다: 초기 연구 질문 제공, 팀 구성, 최종 결과물 리뷰.
